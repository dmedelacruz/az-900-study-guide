## Why Cost Management Matters in the Cloud

In a traditional data center, you pay large upfront costs for servers, networking gear, power, cooling, and building space. These are <KeyTerm term="Capital Expenditures (CapEx)">Upfront spending on physical infrastructure — servers, storage, network equipment, and data center facilities. The cost is incurred before you use the resources and is depreciated over time.</KeyTerm>. You buy the hardware once, use it for years, and replace it when it becomes outdated. The problem? You are guessing at future capacity. Buy too much and money sits idle. Buy too little and you cannot meet demand.

The cloud flips this model to <KeyTerm term="Operational Expenditures (OpEx)">Ongoing spending for services as you use them — like a utility bill. There is no upfront cost for hardware; instead you pay monthly based on actual consumption.</KeyTerm>. Instead of buying a server, you rent computing power by the hour or second. Instead of purchasing a storage array, you pay per gigabyte per month. This is liberating — but it introduces a new challenge: **visibility and control**.

With CapEx, you knew exactly what you spent because you wrote the purchase order. With OpEx, costs can grow silently. A developer spins up a virtual machine for testing and forgets to delete it. A storage account accumulates data nobody uses. An application auto-scales during a traffic spike and stays scaled up. Without active cost management, cloud bills can surprise you.

Azure provides a comprehensive set of tools to help you **estimate** costs before you deploy, **monitor** costs as you consume, and **optimize** spending over time. For the AZ-900 exam, you need to understand the factors that affect cost, the planning calculators, the in-portal cost management tools, and how tags help organize spending.

## Factors That Affect Azure Costs

Azure pricing is not a single number per service — it depends on several variables. Think of it like a phone plan where your bill depends on which plan you chose, how much data you use, where you call, and what extras you added.

### Resource Type

Different Azure services have different pricing models. A virtual machine charges by compute hours (based on the VM size you pick). A storage account charges per gigabyte stored and per transaction. An Azure SQL Database charges based on the performance tier, compute size, and storage consumed. Even within a single service, configuration choices matter — a VM with 64 GB of RAM costs more than one with 4 GB.

<Callout type="info">
For the exam, remember that cost is tied to the **specific configuration** of a resource, not just the resource type. Two virtual machines of different sizes in the same region can have very different prices.
</Callout>

### Consumption Model

Azure offers two primary consumption models:

- **Pay-as-you-go** — you pay for what you use, with no upfront commitment. This offers maximum flexibility but is the most expensive per-unit price.
- **Reserved capacity** — you commit to using a specific amount of a resource (such as a VM size) for one or three years in exchange for a significant discount, often **up to 72% off** pay-as-you-go pricing. The trade-off is reduced flexibility — you pay for the reserved capacity whether you use it or not.

<KeyTerm term="Azure Reservations">A commitment to use a specific Azure resource (such as a virtual machine size or database compute tier) for a one-year or three-year term. In exchange for the commitment, you receive a substantial discount compared to pay-as-you-go pricing.</KeyTerm>

### Geography and Region

Azure operates data centers in regions around the world. Prices vary by region because the cost of power, labor, real estate, and local market conditions differ. For example, running a VM in the US East region may cost less than running the identical VM in Brazil South or Switzerland North. When cost is a priority and latency is not critical, choosing a less expensive region can reduce your bill.

### Network Traffic

<KeyTerm term="Ingress and Egress">Ingress is data flowing into an Azure data center (uploading data to Azure). Egress is data flowing out of an Azure data center (downloading data from Azure or transferring data to another region). Azure generally charges for egress but not for ingress.</KeyTerm>

Network traffic follows a simple rule: **data in is free, data out is charged**. Uploading data to Azure (ingress) costs nothing. Downloading data from Azure or transferring data between regions (egress) incurs bandwidth charges. The more data you move out of Azure, the more you pay. Data transfer between services within the same region is often free or low-cost, while cross-region and internet-bound traffic is more expensive.

<Callout type="tip">
**Exam tip:** Remember the phrase "ingress is free, egress is metered." This is a common exam topic. Also know that data moving between availability zones within the same region incurs a small charge.
</Callout>

### Subscription Type

The type of Azure subscription you use can affect pricing and available offers:

- **Free account** — includes a set of free services for the first 12 months, plus a limited set of always-free services and a one-time $200 credit for the first 30 days.
- **Pay-As-You-Go** — standard pricing with no upfront commitment. Best for individual developers and small workloads.
- **Enterprise Agreement (EA)** — a contractual commitment for large organizations to spend a minimum amount over three years in exchange for discounted pricing and additional benefits.
- **Cloud Solution Provider (CSP)** — purchasing Azure services through a Microsoft partner who provides licensing, billing, and technical support.

<DeepDive title="Spending Limits and Free Account Behavior">
The Azure Free Account includes a $200 credit for the first 30 days. Once the credit is exhausted or the 30 days expire, pay-as-you-go charges begin — but only if you explicitly upgrade the account. If you do not upgrade, the account is disabled and you lose access to resources (though your data is retained for 90 days). This spending limit protects new users from unexpected charges during exploration. Enterprise Agreements and CSP subscriptions do not have the same automatic spending limits — cost management is handled through budgets and alerts instead.
</DeepDive>

## Azure Pricing Calculator

<KeyTerm term="Azure Pricing Calculator">A free web-based tool that lets you estimate the cost of Azure services before you deploy anything. You select products, configure them (region, tier, expected usage), and the calculator produces a monthly cost estimate.</KeyTerm>

The Azure Pricing Calculator is your **pre-deployment planning tool**. Think of it like a restaurant menu with prices — you browse the services, pick what you want, adjust the portions, and see the estimated total before you order.

Here is how it works:

1. **Browse or search** for the Azure services you plan to use (VMs, storage accounts, databases, etc.).
2. **Add them to your estimate** and configure each one — select the region, pricing tier, instance size, expected hours of operation, and expected data volumes.
3. **Review the total** — the calculator shows an estimated monthly cost for each service and the combined total.
4. **Save and share** — you can export the estimate as an Excel spreadsheet or share a link with your team.

The Pricing Calculator does not require an Azure account. Anyone can use it to explore pricing scenarios, compare configurations, or build a budget proposal.

<Callout type="warning">
The Pricing Calculator provides **estimates only** — not guarantees. Actual costs depend on real usage, which may differ from your projections. Use it for planning and budgeting, not as a binding price quote.
</Callout>

## TCO Calculator

<KeyTerm term="Total Cost of Ownership (TCO) Calculator">A free web-based tool that helps you estimate the cost savings of migrating workloads from on-premises infrastructure to Azure. You describe your current on-premises environment, and the calculator compares those costs (hardware, software, power, labor) against the projected Azure costs.</KeyTerm>

While the Pricing Calculator answers "How much will Azure services cost?", the TCO Calculator answers a different question: **"How much will we save by moving to Azure?"**

The TCO Calculator is designed for migration decision-making. It accounts for costs that organizations often overlook when comparing cloud and on-premises:

1. **Define your workloads** — describe your on-premises servers (number, type, CPU, RAM), databases, storage, and network bandwidth.
2. **Adjust assumptions** — the calculator includes default assumptions for electricity costs, IT labor rates, hardware refresh cycles, and software licensing. You can adjust these to match your actual costs.
3. **View the report** — the calculator generates a side-by-side comparison showing your estimated on-premises costs versus Azure costs over a one-year, three-year, or five-year period.

<Callout type="tip">
**Exam tip:** The TCO Calculator is for **comparing on-premises vs. Azure** costs, not for estimating Azure-only costs. If a question asks about estimating costs for new Azure resources, the answer is the Pricing Calculator. If the question involves migration savings or comparing existing infrastructure to Azure, the answer is the TCO Calculator.
</Callout>

<DeepDive title="Hidden Costs the TCO Calculator Captures">
The TCO Calculator reveals costs that are easy to overlook in an on-premises environment:

- **Power and cooling** — electricity to run servers and air conditioning to cool them, which can be 30-60% of data center operating costs.
- **Physical space** — rent or depreciation for the data center floor space your hardware occupies.
- **IT labor** — salaries for system administrators, network engineers, and data center technicians who maintain the hardware.
- **Hardware refresh** — servers typically need replacement every 3-5 years. The TCO Calculator factors in this lifecycle cost.
- **Software licensing** — operating systems, hypervisors, management tools, and backup software licenses that you buy for on-premises but may be included in Azure service pricing.
- **Downtime costs** — the business impact of outages, which are typically more frequent in smaller on-premises environments than in Azure's global infrastructure.

By including all of these factors, the TCO Calculator often shows substantial savings even when the raw compute cost appears similar.
</DeepDive>

## Azure Cost Management + Billing

<KeyTerm term="Azure Cost Management + Billing">A built-in Azure portal tool for monitoring, analyzing, allocating, and optimizing your cloud spending after resources are deployed. It provides cost analysis views, budget creation, spending alerts, and optimization recommendations.</KeyTerm>

The Pricing Calculator and TCO Calculator are planning tools you use before deployment. **Azure Cost Management + Billing** is the tool you use every day after deployment — it is your ongoing dashboard for understanding where your money goes.

### Cost Analysis

Cost Analysis is the core feature. It provides interactive charts and tables that break down your spending by:

- **Service** — which Azure services are costing the most (e.g., Virtual Machines, Storage, SQL Database).
- **Resource group** — which logical groupings of resources are most expensive.
- **Resource** — drill down to the individual resource level to find that forgotten VM or oversized database.
- **Time period** — view daily, weekly, or monthly trends to spot spending spikes.
- **Tag** — filter by resource tags to see costs per department, project, or environment.

### Budgets and Alerts

You can create <KeyTerm term="Azure Budget">A spending threshold you define in Azure Cost Management. When your actual or forecasted spending reaches a specified percentage of the budget, Azure triggers an alert notification (email, webhook, or automation).</KeyTerm> to set spending thresholds and receive notifications when costs approach or exceed those limits.

For example, you might create a $5,000 monthly budget and configure alerts at 50%, 75%, and 100%. When spending reaches $2,500, you get a heads-up. At $3,750, you get a stronger warning. At $5,000, you know you have reached your limit. Alerts can trigger emails, webhook notifications, or even Azure Automation runbooks that automatically shut down non-essential resources.

<Callout type="info">
Budgets in Azure Cost Management are **alerts only** — they do not automatically stop or limit your spending. If you exceed your budget, Azure keeps running your resources and billing you. You must take action yourself (or configure automation) to respond to budget alerts.
</Callout>

### Cost Recommendations

Azure Cost Management integrates with **Azure Advisor** to surface cost optimization recommendations, such as:

- **Shut down or resize underutilized VMs** — if a VM consistently uses less than 5% CPU, Advisor recommends right-sizing or shutting it down.
- **Purchase reserved instances** — if you have VMs or databases running 24/7 for months, Advisor suggests reservations for savings.
- **Delete unused resources** — unattached disks, idle public IP addresses, and empty resource groups that still incur costs.

## Resource Tags for Cost Organization

<KeyTerm term="Resource Tags">Name-value pairs (also called key-value pairs) that you assign to Azure resources, resource groups, and subscriptions to logically organize and categorize them. Tags are metadata — they do not affect how a resource functions, but they enable filtering, grouping, and cost allocation.</KeyTerm>

Tags are like labels on file folders. They do not change what is inside, but they help you find, sort, and categorize things. In the context of cost management, tags let you answer questions like:

- "How much is the Marketing department spending on Azure this month?"
- "What is the total cost of our Production environment versus our Development environment?"
- "Which project is consuming the most storage?"

### How Tags Work

You apply tags as key-value pairs to resources. For example:

| Tag Key | Tag Value |
|---------|-----------|
| Department | Marketing |
| Environment | Production |
| Project | WebsiteRedesign |
| CostCenter | CC-4521 |
| Owner | jsmith@contoso.com |

Once tagged, you can filter Cost Analysis views by any tag to see spending breakdowns by department, project, environment, or any other dimension.

### Tag Inheritance Behavior

<Callout type="warning">
**Critical exam concept:** Tags applied to a resource group are **not inherited** by the resources inside that group. If you tag a resource group with Department:Marketing, the individual VMs, storage accounts, and databases inside that group do **not** automatically receive that tag. You must apply tags to each resource individually, or use Azure Policy to enforce automatic tagging.
</Callout>

Similarly, tags on a subscription are not inherited by the resource groups or resources within it. Each level must be tagged independently. Azure Policy can help automate this by requiring specific tags during resource creation or by inheriting tags from parent resource groups.

<DeepDive title="Tag Enforcement with Azure Policy">
Because tags are optional by default and do not inherit, organizations often struggle with inconsistent tagging — some resources are tagged, others are not, and cost reports have gaps. Azure Policy solves this by letting you create rules such as:

- **Require a tag on resource creation** — any resource created without a specified tag (e.g., CostCenter) is denied. This prevents untagged resources from ever existing.
- **Inherit a tag from the resource group** — automatically copy a tag from the resource group to any resource created within it. This simulates tag inheritance where Azure does not provide it natively.
- **Append a tag with a default value** — if a resource is created without a specific tag, automatically add it with a default value.

For the AZ-900 exam, you do not need to know the details of Azure Policy (that is covered in Section 3.2), but understand that tags alone are passive metadata — you need Policy to enforce consistent tagging.
</DeepDive>
