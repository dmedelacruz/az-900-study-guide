## How Organizations Deploy the Cloud

Not every organization uses the cloud the same way. Some go all-in on a provider like Azure, running every workload on shared infrastructure. Others build their own private cloud environments for maximum control. Many take a blended approach, keeping sensitive systems on private infrastructure while using public cloud for everything else. These different approaches are called **cloud deployment models**, and understanding them is essential for the AZ-900 exam.

Think of it like transportation. **Public transit** — buses, trains, subways — is shared by everyone, costs little per ride, and scales to serve millions of passengers. You don't maintain the vehicles or plan the routes, but you also can't customize the schedule. A **private car** gives you full control over where you go and when, but you pay for the vehicle, insurance, fuel, and maintenance yourself. A **hybrid approach** — driving your car to a park-and-ride station and taking the train downtown — combines the control of private transport with the efficiency of public transit. Cloud deployment models work the same way.

## Public Cloud

<KeyTerm term="Public cloud">A cloud deployment model where computing resources are owned and operated by a third-party cloud provider (such as Microsoft Azure, AWS, or Google Cloud) and delivered over the internet to multiple tenants on a pay-as-you-go basis.</KeyTerm>

In a public cloud, the provider owns everything — the data centers, the servers, the networking equipment, the cooling systems, and the software that orchestrates it all. Multiple organizations (tenants) share this infrastructure, though their data and workloads are logically isolated from each other. You access resources over the internet and pay only for what you consume.

Azure is a public cloud. When you spin up a virtual machine in Azure, you're using hardware that Microsoft owns, in a data center that Microsoft operates, alongside (but isolated from) workloads belonging to other Azure customers.

**Key characteristics of public cloud:**

- **No capital expenditure** — You don't buy servers. You rent computing capacity and pay by the hour, minute, or second.
- **Near-unlimited scalability** — Need 1,000 servers for a product launch? Done. Need to scale back to 10 next week? Also done.
- **Multi-tenant architecture** — Resources are shared across customers, which is how the provider achieves economies of scale and keeps per-unit costs low.
- **Provider-managed infrastructure** — The cloud provider handles hardware maintenance, power, cooling, physical security, and infrastructure software updates.
- **Broad network access** — Resources are accessible from anywhere with an internet connection.

**When to choose public cloud:**

- You want to avoid large upfront hardware investments
- Your workloads have variable or unpredictable demand
- You need to deploy quickly without procuring hardware
- You're running applications that don't have strict data residency or regulatory constraints requiring on-premises hosting

<Callout type="info">
Public cloud doesn't mean your data is public. The word "public" refers to the delivery model — resources are publicly available for purchase — not to the visibility of your data. Your Azure resources are private to you, protected by identity controls, network isolation, and encryption. Other tenants on the same physical hardware cannot see or access your workloads.
</Callout>

## Private Cloud

<KeyTerm term="Private cloud">A cloud deployment model where computing resources are used exclusively by a single organization, either hosted on-premises in the organization's own data center or hosted by a third-party provider in a dedicated environment.</KeyTerm>

A private cloud delivers cloud-like capabilities — self-service provisioning, elasticity, resource pooling — but the infrastructure serves only one organization. This can mean running cloud software (like Azure Stack HCI) in your own data center, or it can mean contracting with a provider to run dedicated hardware exclusively for your organization.

The defining characteristic is single-tenancy: no other organization shares the underlying infrastructure. This gives the organization complete control over the environment, including hardware selection, network configuration, security policies, and data location.

**Key characteristics of private cloud:**

- **Maximum control** — The organization controls hardware, software, network configuration, and security policies.
- **Single-tenant** — No shared infrastructure with other organizations.
- **Higher cost** — The organization bears all capital and operational expenses for the infrastructure.
- **Limited scalability** — Scaling requires purchasing and installing additional hardware, which takes time.
- **On-premises or dedicated hosted** — Can be located in the organization's own data center or in a third-party facility dedicated to that organization.

**When to choose private cloud:**

- Regulatory or compliance requirements mandate that data must stay on specific hardware or within specific physical boundaries
- The organization needs full control over the infrastructure stack for security or governance reasons
- Legacy applications require specific hardware configurations that can't be replicated in a public cloud
- The organization operates in a highly regulated industry (government, defense, certain financial services) where multi-tenant environments are not permitted

<Callout type="warning">
Private cloud is not the same as traditional on-premises IT. Simply running servers in your own data center doesn't make it a private cloud. A true private cloud provides cloud-like features: self-service provisioning, automated scaling (within the hardware available), resource pooling, and metered usage. Without these capabilities, it's just a traditional data center.
</Callout>

## Hybrid Cloud

<KeyTerm term="Hybrid cloud">A cloud deployment model that combines public cloud and private cloud (or on-premises infrastructure), allowing data and applications to move between the two environments. Organizations use hybrid cloud to balance control, compliance, and cost.</KeyTerm>

Hybrid cloud is the "best of both worlds" approach. An organization maintains some infrastructure privately — either on-premises or in a dedicated hosted environment — while also using public cloud services. The two environments are connected and can share data, applications, and workloads.

The key to hybrid cloud is orchestration: the two environments aren't just coexisting side by side — they're integrated. Workloads can move between them, data can flow between them, and management tools can operate across both. Azure Arc, for example, lets organizations manage on-premises servers, Kubernetes clusters, and data services using the same Azure portal and tools they use for public cloud resources.

**Key characteristics of hybrid cloud:**

- **Flexibility** — Run workloads wherever they make the most sense: sensitive data on private infrastructure, scalable web frontends on public cloud.
- **Compliance bridge** — Keep regulated data on-premises while still using public cloud for non-regulated workloads.
- **Gradual migration path** — Organizations can move to the cloud incrementally rather than all at once.
- **Increased complexity** — Managing two environments requires integration, networking (VPNs, ExpressRoute), and consistent security policies across both.
- **Cost optimization** — Use private infrastructure for steady baseline workloads and burst to public cloud for spikes.

**When to choose hybrid cloud:**

- Some workloads must remain on-premises due to compliance, latency, or data sovereignty requirements, but other workloads benefit from public cloud scalability
- The organization is in the middle of a cloud migration and needs to run in both environments during the transition
- Seasonal or unpredictable demand spikes need public cloud capacity while baseline operations run on private infrastructure
- The organization wants to keep legacy systems on-premises while building new applications in the cloud

<Callout type="tip">
For the AZ-900 exam, hybrid cloud is a frequent topic. Remember that hybrid cloud isn't just "some on-premises, some cloud" — it requires integration between the two environments. Azure provides specific tools for hybrid scenarios: Azure Arc for unified management, Azure Stack HCI for running Azure services on-premises, and ExpressRoute for private, high-bandwidth connections between on-premises networks and Azure.
</Callout>

## Multi-Cloud

<KeyTerm term="Multi-cloud">A strategy where an organization uses cloud services from two or more public cloud providers — for example, running some workloads on Azure and others on AWS or Google Cloud.</KeyTerm>

Multi-cloud is distinct from hybrid cloud. Hybrid cloud combines public and private environments; multi-cloud combines multiple public cloud providers. Organizations adopt multi-cloud strategies for several reasons: avoiding vendor lock-in, leveraging best-of-breed services from different providers, or meeting requirements from clients or partners who mandate specific platforms.

Azure Arc supports multi-cloud scenarios by letting organizations manage resources across Azure, AWS, and Google Cloud from a single control plane.

<Callout type="info">
Multi-cloud adds operational complexity — each provider has different APIs, pricing models, security tools, and networking architectures. On the AZ-900 exam, you should understand what multi-cloud means and why organizations use it, but detailed multi-cloud architecture is beyond the scope of the exam.
</Callout>

## Cloud Bursting

<KeyTerm term="Cloud bursting">A hybrid cloud technique where an application normally runs on private infrastructure but automatically "bursts" into the public cloud when demand exceeds the private environment's capacity.</KeyTerm>

Cloud bursting is a specific pattern within hybrid cloud deployments. An organization runs its application on private infrastructure under normal conditions but has configured the system to automatically provision additional resources in the public cloud during demand spikes. Once demand subsides, those public cloud resources are released. This lets organizations size their private infrastructure for average workloads rather than peak workloads, reducing waste.

## Comparing Cloud Models

| Dimension | Public Cloud | Private Cloud | Hybrid Cloud |
|---|---|---|---|
| **Ownership** | Cloud provider owns infrastructure | Organization owns or leases dedicated infrastructure | Mix of both |
| **Capital expenditure** | None — pay-as-you-go | High — must purchase or lease hardware | Moderate — CapEx for private, OpEx for public |
| **Scalability** | Near-unlimited, on-demand | Limited to available hardware | Flexible — burst to public cloud when needed |
| **Control** | Limited to provider's configuration options | Full control over hardware, software, and policies | Full control on private side; provider controls on public side |
| **Security responsibility** | Shared responsibility model | Organization controls all layers | Split across environments |
| **Compliance** | Provider certifications (SOC 2, ISO, etc.) | Organization manages all compliance | Sensitive workloads stay on compliant private infrastructure |
| **Maintenance** | Provider handles infrastructure maintenance | Organization handles all maintenance | Split responsibility |
| **Speed of deployment** | Minutes | Weeks to months (hardware procurement) | Minutes for public, longer for private |
| **Multi-tenancy** | Yes — shared infrastructure | No — single tenant | Private portion is single-tenant |

<DeepDive title="Hybrid Cloud Use Cases in the Real World">
Hybrid cloud isn't just a theoretical concept — it's how most large organizations actually operate today. Here are three common patterns:

**Compliance-driven placement.** A healthcare organization runs its electronic health records system on private infrastructure to meet HIPAA data residency requirements, but uses Azure for its patient-facing appointment scheduling portal. The two systems exchange data through secure, encrypted connections, but the most sensitive data never leaves the private environment.

**Cloud bursting for demand spikes.** An e-commerce retailer runs its core platform on private servers that handle normal daily traffic. During Black Friday and holiday sales, traffic surges to 20x normal levels. Rather than buying hardware that sits idle 50 weeks a year, the retailer bursts into Azure to handle the spike, then releases those resources when demand returns to baseline.

**Gradual cloud migration.** A manufacturing company with 15 years of on-premises applications doesn't migrate everything to Azure overnight. They start by moving development and testing workloads to the public cloud, then gradually migrate production systems over 18 months. During the migration period, they operate in a hybrid model with some applications on-premises and others in Azure, connected through a VPN gateway.
</DeepDive>

<DeepDive title="Multi-Cloud vs. Hybrid Cloud: What's the Difference?">
These two terms are frequently confused, but they describe different architectural choices:

**Hybrid cloud** combines public cloud with private cloud or on-premises infrastructure. The defining feature is mixing cloud with non-cloud (or dedicated cloud) environments. Example: running a database on-premises and a web application in Azure.

**Multi-cloud** combines multiple public cloud providers. The defining feature is using more than one provider. Example: running a machine learning workload on Google Cloud while hosting the web application on Azure.

An organization can be both hybrid and multi-cloud simultaneously — for example, running some workloads on-premises, some in Azure, and some in AWS. This is increasingly common in large enterprises, though it adds significant management complexity.

On the AZ-900 exam, you need to distinguish between these concepts. If a question describes an organization using Azure and on-premises servers together, that's hybrid. If it describes an organization using Azure and AWS together, that's multi-cloud.
</DeepDive>

<KeyTakeaways>
- **Public cloud** is owned by the provider, shared across tenants, and uses a pay-as-you-go model — offering maximum scalability with no capital expenditure but less control over the underlying infrastructure.
- **Private cloud** is dedicated to a single organization, offering full control over hardware, security, and compliance — but at higher cost and with limited scalability.
- **Hybrid cloud** combines public and private environments with integration between them, allowing organizations to place workloads where they make the most sense based on compliance, cost, and performance needs.
- **Multi-cloud** means using multiple public cloud providers (e.g., Azure and AWS together) — distinct from hybrid cloud, which mixes public with private.
- **Cloud bursting** is a hybrid pattern where applications normally run on private infrastructure but burst into the public cloud during demand spikes.
- The word "public" in public cloud refers to the delivery model, not the visibility of your data — your Azure resources are private and protected.
- Hybrid cloud requires actual integration between environments (via tools like Azure Arc, VPN Gateway, or ExpressRoute), not just separate systems running side by side.
- Most large organizations today use hybrid or multi-cloud strategies, not a single model exclusively.
</KeyTakeaways>
