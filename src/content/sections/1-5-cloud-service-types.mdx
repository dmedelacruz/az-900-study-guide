## Renting an Apartment, a Kitchen, or a Meal

Think about three ways to eat dinner tonight. You could **rent an empty apartment** — you get the building and utilities, but you bring your own furniture, cookware, and ingredients, and you cook the meal yourself. You could **rent a fully equipped commercial kitchen** — the ovens, counters, and utensils are provided and maintained for you, and you just bring your recipe and ingredients. Or you could **order a meal at a restaurant** — someone else handles everything from sourcing ingredients to cooking to serving, and you simply sit down and eat.

Cloud service types work the same way. <KeyTerm term="Infrastructure as a Service (IaaS)">A cloud service type that provides virtualized computing infrastructure — virtual machines, networking, and storage — on demand. The cloud provider manages the physical hardware, and you manage everything from the operating system up, including middleware, runtime, data, and applications.</KeyTerm> gives you the empty apartment. <KeyTerm term="Platform as a Service (PaaS)">A cloud service type that provides a managed platform for developing, running, and managing applications without dealing with underlying infrastructure. The cloud provider manages hardware, operating system, middleware, and runtime, and you manage your application code and data.</KeyTerm> gives you the equipped kitchen. <KeyTerm term="Software as a Service (SaaS)">A cloud service type that delivers fully complete software applications over the internet on a subscription basis. The cloud provider manages everything — infrastructure, platform, and application — and you simply use the software through a browser or app.</KeyTerm> gives you the restaurant meal. Each service type represents a different division of responsibility between you and the cloud provider, and understanding that division is a core AZ-900 topic.

## Infrastructure as a Service (IaaS)

IaaS is the most flexible cloud service type. The cloud provider gives you access to fundamental computing resources — virtual machines, virtual networks, and storage — and takes care of the physical infrastructure underneath. You are responsible for everything above the hardware layer: installing and patching the operating system, configuring middleware and runtime environments, deploying your applications, and managing your data.

**What Azure provides (the provider manages):**

- Physical servers, storage hardware, and networking equipment
- The data center facility (power, cooling, physical security)
- The virtualization layer (hypervisor)

**What you manage:**

- Operating system (installation, patching, updates)
- Middleware and runtime environments
- Application deployment and configuration
- Data storage, backup, and security
- Network configuration (firewalls, load balancers, DNS)

**Common Azure IaaS services:**

- **Azure Virtual Machines** — Run Windows or Linux VMs with full OS-level control
- **Azure Virtual Network** — Create isolated networks, subnets, and VPN connections
- **Azure Disk Storage** — Persistent block storage for VMs
- **Azure Load Balancer** — Distribute traffic across VMs you manage

**When to use IaaS:**

- You need full control over the operating system and runtime environment
- You're running custom or legacy applications that require specific OS configurations
- You want to migrate on-premises workloads to the cloud with minimal changes (lift-and-shift)
- You need to run software that can't be hosted on a managed platform

<Callout type="info">
IaaS is often the first step in a cloud migration because it most closely mirrors a traditional on-premises environment. Organizations can move existing VMs to Azure with minimal modification — a strategy called "lift-and-shift." Over time, they may refactor applications to take advantage of PaaS services for reduced management overhead.
</Callout>

## Platform as a Service (PaaS)

PaaS provides a complete, managed environment for building and deploying applications. The cloud provider handles not just the physical infrastructure but also the operating system, middleware, runtime, and development tools. You focus entirely on writing your application code and managing your data — the platform takes care of everything underneath.

**What Azure provides (the provider manages):**

- Everything IaaS provides (physical infrastructure + virtualization)
- Operating system (patching, updates, security)
- Middleware and runtime environments
- Development tools, database management, and business analytics

**What you manage:**

- Application code and logic
- Data and data access
- Application-level security settings (authentication, authorization)

**Common Azure PaaS services:**

- **Azure App Service** — Host web apps, REST APIs, and mobile backends without managing servers
- **Azure SQL Database** — Fully managed relational database with built-in high availability
- **Azure Functions** — Run event-driven code without provisioning or managing servers (serverless)
- **Azure Cosmos DB** — Globally distributed NoSQL database

<KeyTerm term="Serverless computing">A form of PaaS where the cloud provider dynamically allocates and manages all infrastructure. You write and deploy code (typically as functions), and the provider handles scaling, patching, and capacity planning automatically. You pay only for actual execution time, not for idle capacity.</KeyTerm>

**When to use PaaS:**

- You want to focus on application development without managing infrastructure
- You need built-in scalability, patching, and high availability
- You're building new cloud-native applications from scratch
- You want to reduce the operational burden on your IT team

<Callout type="tip">
For the AZ-900 exam, remember that PaaS is ideal when your goal is to develop and deploy applications quickly. You trade some control over the underlying infrastructure for dramatically reduced management overhead. If a question describes a development team that wants to deploy a web app without worrying about OS patches or server management, PaaS is the answer.
</Callout>

## Software as a Service (SaaS)

SaaS delivers fully functional software applications over the internet. You don't install, configure, or maintain anything — you simply access the application through a web browser or dedicated app. The cloud provider manages the entire stack, from physical infrastructure to application code, updates, and availability.

**What Azure/Microsoft provides (the provider manages):**

- Everything PaaS provides (infrastructure + platform)
- Application code and updates
- Application availability and performance
- Feature development and release cycles

**What you manage:**

- Your data within the application (documents, emails, records)
- User accounts and access permissions
- Organization-specific configuration settings

**Common Microsoft SaaS services:**

- **Microsoft 365** — Email (Outlook), documents (Word, Excel, PowerPoint), collaboration (Teams)
- **Microsoft Dynamics 365** — Customer relationship management (CRM) and enterprise resource planning (ERP)
- **Microsoft Power BI** — Business intelligence and data visualization

<KeyTerm term="Multi-tenant architecture">A software design where a single instance of the application serves multiple customers (tenants), with each tenant's data isolated from others. Most SaaS applications use multi-tenant architecture to achieve economies of scale — one codebase, one set of infrastructure, shared across thousands of organizations.</KeyTerm>

**When to use SaaS:**

- You need a standard application like email, collaboration, or CRM
- You want to avoid all infrastructure and application management
- You need to deploy a solution quickly with minimal setup
- You prefer predictable, subscription-based pricing

<Callout type="warning">
SaaS offers the least customization of the three service types. You get the application as the provider built it, with configuration options limited to what the provider exposes. If you need highly customized software or full control over the application's behavior, SaaS may not be the right fit — consider PaaS (build your own) or IaaS (run your own) instead.
</Callout>

## Comparing Cloud Service Types

| Dimension | IaaS | PaaS | SaaS |
|---|---|---|---|
| **You manage** | OS, middleware, runtime, apps, data | Apps and data | Data and configuration |
| **Provider manages** | Hardware, networking, virtualization | Hardware through runtime | Everything |
| **Flexibility** | Highest — full OS control | Moderate — app-level control | Lowest — use as provided |
| **Management overhead** | Highest — you manage most layers | Moderate — provider handles platform | Lowest — just use the software |
| **Use case** | VM migrations, custom environments | App development, databases | Email, CRM, collaboration |
| **Azure examples** | Virtual Machines, Virtual Networks | App Service, SQL Database, Functions | Microsoft 365, Dynamics 365 |
| **Scaling** | You configure scaling rules | Platform handles most scaling | Provider handles all scaling |

## The Responsibility Spectrum

Cloud service types exist on a spectrum of control and responsibility. As you move from IaaS to PaaS to SaaS, two things happen simultaneously: the cloud provider takes on more management responsibility, and you give up more control over the underlying layers.

- **IaaS** sits at the "most control, most responsibility" end. You control the OS, middleware, runtime, and applications — but you're also responsible for patching, securing, and maintaining all of those layers. If the OS has a vulnerability, it's your job to patch it.
- **PaaS** occupies the middle ground. The provider manages the OS, middleware, and runtime, so you don't worry about patches or infrastructure scaling. You focus on your application code and data. You have less control over the platform's behavior but far less operational burden.
- **SaaS** sits at the "least control, least responsibility" end. The provider manages everything, including the application itself. You simply use the software. You can't customize the underlying code, but you also never need to deploy, patch, or scale anything.

This spectrum directly maps to the <KeyTerm term="Shared responsibility model">A framework that defines which security and management tasks are handled by the cloud provider and which are handled by the customer. The division of responsibility shifts depending on the cloud service type — IaaS places more responsibility on the customer, while SaaS places more on the provider.</KeyTerm> covered in Section 1.2. The more the provider manages, the fewer layers you need to secure and maintain — but the less flexibility you have to customize those layers.

<DeepDive title="Real-World Example: Building a Web Application — Three Approaches">
Imagine your team needs to deploy a customer-facing web application with a database backend. Here's how each service type approaches the same goal:

**IaaS approach (Azure Virtual Machines):** You create a VM, install your preferred Linux distribution, configure Nginx as a web server, install Node.js, deploy your application code, set up a separate VM for your database, configure networking between the two, set up backup scripts, and create monitoring alerts. You control every detail — but you're also responsible for OS patches, security updates, database backups, SSL certificate renewal, and scaling. If traffic doubles, you need to provision and configure additional VMs manually (or set up auto-scaling rules).

**PaaS approach (Azure App Service + Azure SQL Database):** You push your application code to Azure App Service. Azure handles the web server, OS patching, SSL, and load balancing. Your database runs on Azure SQL Database, which handles backups, high availability, and performance tuning automatically. If traffic doubles, you adjust a scaling slider or configure auto-scale rules — no new VMs to provision or configure. You shipped the same application in a fraction of the time and with far less ongoing maintenance.

**SaaS approach (not applicable here):** SaaS wouldn't work for a custom web application because SaaS provides pre-built software, not a platform for building your own. However, if the need were "we need a CRM to track customer interactions" rather than "we need a custom web app," then a SaaS solution like Dynamics 365 would deliver that capability instantly — no development required at all.

The right choice depends on what you need: maximum control (IaaS), rapid development with managed infrastructure (PaaS), or an off-the-shelf solution (SaaS).
</DeepDive>

<DeepDive title="The Shared Responsibility Model by Service Type">
The shared responsibility model (covered in detail in Section 1.2) divides security and management tasks between you and the cloud provider. The division shifts significantly depending on which service type you use:

**Responsibilities that are always the provider's** (regardless of service type):
- Physical data center security (fences, guards, biometrics)
- Physical hardware maintenance and replacement
- Network infrastructure and power/cooling
- Hypervisor security and patching

**Responsibilities that are always yours** (regardless of service type):
- Your data and information — even in SaaS, your documents, emails, and records are your responsibility to classify and protect
- Your accounts and identities — user access management, passwords, multi-factor authentication
- Your devices — the laptops and phones your employees use to access cloud services

**Responsibilities that shift based on service type:**
- **Operating system patching:** Your job in IaaS, provider's job in PaaS and SaaS
- **Network controls and firewalls:** Your job in IaaS, shared in PaaS, provider's job in SaaS
- **Application security:** Your job in IaaS and PaaS, provider's job in SaaS
- **Identity and directory infrastructure:** Shared across all types, but you have more direct control in IaaS

Understanding this shift is critical for the exam. A common question pattern presents a scenario and asks who is responsible for a specific task — and the answer depends on which service type is being used.
</DeepDive>

<KeyTakeaways>
- **IaaS** provides virtualized infrastructure (VMs, networking, storage). You manage the OS, middleware, runtime, apps, and data. The provider manages physical hardware and virtualization. Use IaaS for lift-and-shift migrations and workloads requiring full OS control.
- **PaaS** provides a managed platform for building applications. The provider manages infrastructure through the runtime layer. You manage only your application code and data. Use PaaS for new app development and managed databases.
- **SaaS** delivers complete, ready-to-use applications over the internet. The provider manages everything. You manage your data and user configuration. Use SaaS for standard applications like email, CRM, and collaboration.
- Cloud service types exist on a **responsibility spectrum**: IaaS gives the most control and responsibility, SaaS gives the least. PaaS sits in the middle.
- The **shared responsibility model** shifts depending on the service type — the more the provider manages, the fewer layers you need to secure and maintain.
- Common Azure examples: IaaS = Virtual Machines, Virtual Networks; PaaS = App Service, SQL Database, Functions; SaaS = Microsoft 365, Dynamics 365.
- **Serverless computing** (e.g., Azure Functions) is a form of PaaS where the provider manages all infrastructure and scales dynamically — you pay only for execution time.
- Regardless of service type, the customer is **always responsible** for their own data, accounts, identities, and devices.
</KeyTakeaways>
